# IGCSE Physics Video Engine — End-to-End Runbook

This repository now contains the reusable source needed to prepare, generate, preview, and render one syllabus topic at a time. It has no runtime dependency on the two original external source repositories.

## 1. Components

```text
pilot/output/syllabus_topics.json        58 topics and 328 raw syllabus rows
video_engine/curriculum/objectives.json  324 teachable objectives (headers removed)
pilot/index_output/question_index.sqlite3
                                          private aggregate assessment patterns
video_engine/                             curriculum, coverage, and topic preparation
physics_animation_engine/                 deterministic module and typed-recipe runtimes
template_lab/                              narration, TTS, timing, V3 scenes, preview, MP4
```

Template Lab now routes scenes objective-first. Each narration beat retains its
syllabus objective IDs, and a deterministic local selector chooses a typed visual
recipe that is allowed for those objectives. The browser compiles the recipe into
safe DOM/SVG/GSAP using reusable workbenches; no scene HTML, CSS, or JavaScript is
generated by a model. A legacy module/custom-model route exists only as an explicit
fallback for objectives that do not yet have recipes.

The private past-paper index is used only to count patterns such as command words, question types, difficulty, and use of visuals. Raw question text and screenshots are never inserted into a generation packet.

## 3. Configure only the providers you use

```bash
cp .env.example .env
```

At minimum, the recommended V3 route needs:

```text
GEMINI_API_KEY      script and Gemini TTS
ZAI_API_KEY         optional custom-scene fallback for uncovered objectives
```

Anthropic, Moonshot, and ElevenLabs are optional alternatives. `.env` is ignored by Git. Every paid generation command must include `--confirm-paid-api`.

## 4. Prepare one topic

```bash
python3 -m video_engine.cli status
python3 -m video_engine.cli next-topic
python3 -m video_engine.cli prepare-topic 1.1
```

The final command creates:

```text
video_engine/topics/1.1/facts.json
```

It contains stable syllabus objective IDs, Core/Supplement labels, private aggregate assessment patterns, and a strict originality boundary. Existing packets are not overwritten unless `--force` is supplied.

Before generation, add trusted teacher-authored facts to the packet when the syllabus objective alone is not enough to ground an explanation, worked example, practical method, or misconception correction. Each added fact needs a unique `id`, exact `text`, and a `source` note.

## 5. Generate the lesson manually

```bash
RUN_ID=physics-1-1-v01

python3 template_lab/scripts/mav_generate.py \
  --run-id "$RUN_ID" \
  --facts video_engine/topics/1.1/facts.json \
  --duration 480 \
  --v3 \
  --use-gemini \
  --use-gemini-tts \
  --confirm-paid-api
```

The default 480-second target produces duration-aware word and paragraph bounds. The physics prompts require concept-first teaching, prediction/retrieval pauses, correct units and diagram geometry, original examples, and strict claim IDs. Generated narration fails the run instead of silently continuing when it violates the bounds or grounding checks.

### What happens during scene generation

1. The application uses word timestamps and semantic punctuation to split narration
   into visual beats. Defaults target 11 seconds, cap a beat at 15 seconds, and merge
   fragments shorter than 5 seconds where the meaning remains continuous.
2. Claim IDs are converted to stable objective IDs. Selection is constrained to
   recipes registered for those objectives, so prose similarity cannot silently
   route a scene to an unrelated visual.
3. The selector deterministically balances beat labels, cue terms, and repeated use
   to vary the visuals while remaining inside the grounded objective set.
4. The local `RecipeScene` compiler validates normalized geometry, node types,
   workbenches, actions, timing, and safe text, then constructs the DOM/SVG/GSAP
   animation. Recipes cannot inject HTML, CSS, JavaScript, or remote assets.
5. `objective_recipe_coverage.json` records covered and uncovered visual beats. If
   model fallback is disabled, any uncovered beat stops Step 5 with a clear error.
6. Only when a model provider is explicitly enabled may uncovered beats use the
   older shortlist/router/module/custom path. Covered beats never call those models.
7. The preview builder places recipe, module, and any explicit fallback scenes on
   one master GSAP timeline. HyperFrames/FFmpeg rendering is unchanged.

### Deterministic recipe coverage

The reusable compiler vocabulary is syllabus-wide: it declares 11 physics
workbenches and typed primitives for apparatus, vectors, graphs, particles, fields,
circuits, equations, timelines, labels, comparison bars, and staged actions. The
curated curriculum catalogue contains 58 topics and 324 teachable objectives; the
four additional raw syllabus rows are section headings, not learning objectives.

Recipe content is intentionally expanded objective by objective. The current
registry contains 18 variants covering all seven objectives in Topic 1.1. The other
objectives are not claimed as covered yet; add grounded recipes to
`template_lab/assets/objective_visual_recipes.json` before running them without a
fallback. This makes missing assets visible instead of producing a generic but
technically valid scene.

## 6. Review and repair without repeating paid work

```bash
python3 template_lab/scripts/mav_preview.py --run-id "$RUN_ID" --port 8766
```

Review physics accuracy, objective coverage, pacing, visual clarity, and originality.
This review is deliberately manual; there is no subjective automated visual-QA gate.
The pipeline retains only schema, HTML/GSAP safety, and render-integrity checks.
Cached artifacts let you restart from a later stage:

```bash
# Rebuild/validate cached local recipe scenes without regenerating script or audio.
python3 template_lab/scripts/mav_generate.py \
  --run-id "$RUN_ID" \
  --facts video_engine/topics/1.1/facts.json \
  --duration 480 \
  --v3 \
  --from-step 6
```

After changing segmentation, selection, or recipe timing, regenerate from Step 5 so
routes match the new visual-beat IDs. For a fully covered topic this is local and
does not require a scene model:

```bash
python3 template_lab/scripts/mav_generate.py \
  --run-id "$RUN_ID" \
  --facts video_engine/topics/1.1/facts.json \
  --duration 480 \
  --v3 \
  --from-step 5 \
  --stop-after-step 7
```

If coverage is incomplete, that command fails and names the uncovered scenes. Add
recipes, or explicitly enable and confirm a paid model provider if you choose to use
the legacy fallback.

Shot timing can be tuned without code changes using
`MAV_V3_MIN_SHOT_SECONDS`, `MAV_V3_TARGET_SHOT_SECONDS`, and
`MAV_V3_MAX_SHOT_SECONDS`. Keep `MIN <= TARGET <= MAX`.

Regenerating a model-driven step is a paid action; the guard remains in force. Never use `--clean` casually on a paid run because it removes cached artifacts.

## 7. Render the approved MP4

```bash
python3 template_lab/scripts/mav_render.py \
  --run-id "$RUN_ID" \
  --quality high \
  --fps 30
```

The renderer builds the current V3 composition, renders its visual stream with the pinned local HyperFrames package, muxes `voiceover.mp3` with FFmpeg, and checks that the result contains video and audio streams. The default output is:

```text
template_lab/runs/<run-id>/renders/master_v3.mp4
```

## 8. Update coverage only after human review

```bash
python3 -m video_engine.cli set-status --topic 1.1 --status reviewed
python3 -m video_engine.cli set-status --topic 1.1 --status covered
python3 -m video_engine.cli status
```

Use explicit objective IDs when a video covers only part of a topic:

```bash
python3 -m video_engine.cli set-status \
  --objective-ids 1.2-C01 1.2-C02 1.2-C03 \
  --status covered
```

Uploading is a separate, explicitly confirmed stage. The local Studio YouTube control room can publish approved long-form lessons and Reels through saved channel profiles; the engine still has no unattended scheduler.
